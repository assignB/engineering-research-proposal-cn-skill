# 中文工科科研调研、技术论证与项目申报书 Skill

这是一个面向中文工科科研写作的 Codex Skill，主要用于电子信息、通信、电力、自动化及相关交叉工程领域的科研调研、技术论证、项目申报书编写、Word 排版和团队合稿。

本 Skill 支持个人完成单个章节，也支持在用户明确负责合稿时，将多个成员提交的文档按照指定模板合并为完整技术文档。

## 安装方法

在本地 Codex 中输入：

```text
$skill-installer 请从下面的 GitHub 地址安装这个 Skill：
https://github.com/assignB/engineering-research-proposal-cn-skill/tree/main/engineering-research-proposal-cn
```

安装完成后，在下一轮对话中输入：

```text
$engineering-research-proposal-cn
```

如果安装后没有立即显示，请重新启动 Codex。

## 基本使用方法

### 编写个人负责章节

```text
$engineering-research-proposal-cn

请按照我提供的模板和资料编写项目申报书。我负责研究内容四，同时负责国内外研究水平综述、理论和实践依据以及项目研究关键和难点中与研究内容四对应的部分。
```

团队协作时，建议明确说明：

- 自己负责的研究内容或章节；
- 负责到哪一级标题；
- 需要编写多少个同级标题；
- 是否已经确定标题名称和编号；
- 是否需要与其他成员文档合并；
- 需要单独交付章节，还是写入完整模板。

### 编写整篇文档

```text
$engineering-research-proposal-cn

请根据我提供的项目材料和申报模板编写完整项目申报书。先分析模板结构、材料完整性、指标来源和需要补充的论文，再开始撰写。
```

### 合并团队文档

只有在用户明确表示自己负责合稿，或明确要求生成完整总文档时，Skill 才会进入整篇合稿模式。

```text
$engineering-research-proposal-cn

我负责本项目的最终合稿。请以“项目申报书模板.docx”作为整体结构和排版标准，将各成员提交的研究内容文档合并成完整文档。
```

合稿时默认尽量保留各成员文档的全部原始内容，只对标题、顺序、编号、衔接词和格式进行必要调整。重复内容、内容冲突或无法确定落位的内容不会被静默删除，而是整理成待确认清单交给合稿负责人。

### 修改已有文档

```text
$engineering-research-proposal-cn

请检查并完善这份 Word 文档，重点处理标题层级、导航窗格、括号序号、图表编号、公式格式、分页符和模板化表达，不要改变原有技术含义和指标。
```

## 建议提供的材料

为了获得更完整、准确的结果，建议提供以下材料。

### 必要材料

- 项目申报书、技术报告或科研报告模板；
- 项目背景、研究目标和研究内容；
- 用户本人负责的章节或研究内容；
- 已有技术方案、需求书、任务书或项目说明；
- 已确定的专业术语和缩略语；
- 已有指标及其来源。

### 推荐材料

- 近几年相关中文论文；
- 必要的英文论文、标准、专利或行业报告；
- 现有系统说明、设备资料和接口文件；
- 已有图表、公式和试验资料；
- 团队分工表或研究内容分工 Excel；
- 可供参考的正式项目文档；
- Visio 图样例或现有 VSDX 文件。

如果暂时没有论文，可以先要求 Skill 分析还需要哪些论文。Skill 会优先推荐真实存在、近几年发表且与研究内容直接相关的中文论文，并辅以必要的英文论文。用户下载论文后再提供给 Codex，可以进一步提高正文质量。

## 使用前需要明确的事项

### 模板标准

如果提供了多个 Word 文档，应明确哪一份作为字体、字号、间距、标题层级、编号和图表形式的标准。

如果参考模板属于其他项目，只希望学习形式，请明确说明：

```text
只学习该模板的字体、字号、间距、标题层级、编号和图表形式，不采用其中的技术内容、指标和结论。
```

### 负责范围

团队协作时应说明：

- 负责哪个研究内容；
- 负责哪些一级、二级或三级章节；
- 是否还负责其他大章节中与该研究内容对应的内容；
- 是否只生成个人章节；
- 是否明确负责最终合稿。

仅仅说明“以后需要与别人合并”，不会自动进入整篇合稿模式。

### 指标处理

涉及精度、时延、容量、成功率、灵敏度、信噪比或考核指标时，应明确：

- 是否需要写出确定数值；
- 是否只能采用用户材料中的指标；
- 是否允许根据论文或标准提出建议值；
- 未确定的指标是否保持定性描述。

如果没有获得确认，Skill 不会擅自把指标写死。

### 正文修改范围

合稿或修改已有文档时，默认优先保留原始内容，只进行必要的标题、顺序、编号、格式和衔接调整。

如果允许较大幅度润色，应明确说明：

```text
允许在不改变技术含义、指标和引用关系的前提下统一全文语言风格，删减重复内容并弱化模板化表达。
```

## Word、公式和 Visio 说明

### Word 格式

Skill 会优先按照用户指定模板设置：

- 中文和英文字体；
- 字号和行距；
- 段前段后与首行缩进；
- 标题层级和导航窗格；
- 图表题注；
- 页眉页脚；
- 分项编号；
- 参考文献格式。

正文原则上采用自然分页，不通过每页插入分页符的方式凑页数。

### MathType 公式

Skill 会优先保留或生成真实可编辑的 MathType 公式。

如果当前运行环境无法可靠完成 MathType 转换，可能会先交付 Word 原生公式，并明确提醒用户在 Word 的 MathType“转换公式”功能中自行转换。

Word 原生公式会预先按照“公式居中、编号右对齐”的方式排版。用户转换为 MathType 后，仍需检查：

- 公式是否保持居中；
- 编号是否保持右对齐；
- 是否出现乱码或异常空格；
- 上下标、分式和矩阵是否完整；
- 公式中是否残留中文逗号或其他异常符号。

### Visio 图

工程图默认采用正规的论文式框图风格：

- 框体横平竖直；
- 同层级框体尺寸一致；
- 对齐和间距统一；
- 连接线连接到图形边缘；
- 默认不超过三种低饱和浅色；
- 避免过于复杂或过于简单。

如果要求在 Word 中双击图形后直接打开 Visio，应明确提出：

```text
请把 VSDX 作为真实 Visio OLE 对象嵌入 Word，不要只插入图片。
```

能否在 Word 中直接编辑，还取决于本机是否安装 Microsoft Visio。

## 团队合稿说明

进入整篇合稿模式后，Skill 会：

1. 确认用于合稿的标准模板或标准文档；
2. 建立来源文档与目标章节的对应关系；
3. 将各成员内容放入模板中的正确位置；
4. 尽量完整保留原有正文、图表、公式和引用；
5. 统一标题、编号、字体、图表和参考文献；
6. 检查提示词残留和模板化表达；
7. 检查重复内容、冲突内容和缺失栏目；
8. 生成未落位与冲突清单；
9. 完成全文结构检查和逐页排版检查。

所谓“AI 味道”只作为写作质量问题处理，不会仅凭行文风格判断作者是否使用了 AI。检查重点包括提示词残留、机械化句式、空泛总结、无依据的拔高表述和重复套话。

## 推荐提示词

```text
$engineering-research-proposal-cn

请先读取我提供的模板、项目材料和参考论文，再开始工作。

我的负责范围是：
1. 研究内容四；
2. 国内外研究水平综述中研究内容四对应部分；
3. 理论和实践依据中研究内容四对应部分；
4. 项目研究关键和难点中研究内容四对应部分。

请先确认标题层级、标题数量、指标处理方式和需要补充的材料。正文尽量复用项目材料和本领域常用专业术语，不自行创造新概念。涉及指标时不要擅自写死。公式保持居中、编号右对齐；Visio 图采用不超过三种浅色的正规工程框图。
```

## 注意事项

- 不虚构论文、标准、专利、数据、指标或试验结论；
- 不把 Word 原生公式冒充为 MathType；
- 不把普通图片冒充为可编辑 Visio 对象；
- 不擅自修改用户材料中已经确定的指标；
- 不在正式正文中保留提示词、编制过程说明或团队合稿提示语；
- 不在未经确认的情况下删除团队成员提交的实质性内容；
- 自动生成的技术文档仍需项目负责人进行最终技术审核。
